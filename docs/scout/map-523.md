## Three F-without-empty claims — grilled live; driver now honest

### 1. Elliptic / Bézier do not refuse

**Confirmed.** Parse accepts `E` / `B` (`oracle/driver.ml:3816–3823`).
Two paths then treat them as empty or as a proxy, never as a refuse:

- **Lineal** `pair_pts` returns `[]` for any E/B pair (`3983–3985`).
  Empty contact ⇒ `disjoint` ⇒ `"FFFFFFFFF"` (`4080`, `4090`).
- **Areal** is worse than `[]`. Elliptic×chord is a zero-length chord at
  the centre (`4195–4197`). Bézier×chord is the control chord
  (`4198–4200`). Same-type E/B pairs return `[]` (`4201–4204`).
  `point_in_ring` ignores elliptic (`4236`) and ray-casts the Bézier
  control chord (`4237–4238`). `seg_point` samples the Bézier chord
  (`4303–4305`) and the elliptic centre (`4306–4308`).

The buffer precedent the issue names is still true: `BUFFER_REGION`
(`3353`), `BUFFER_UNIFIED` (`3482`), and `ARC_BUFFER_SIMPLE` (`3372`)
`failwith` on anything but `C` / `A`. `LENGTH_UNIFIED` accepts E/B and
computes — so “all four `parse_seg`s failwith” is slightly overstated;
the buffer modes do.

Same shape as #511 (elliptic no-op in `RING_ORIENTATION` /
`POINT_IN_CURVE_RING`). Year 1 is circular. Refuse is the honest
interim, not zoo carriers.

### 2. Undistinguishable cells are filled `F` by construction

**Confirmed.** Header `3801–3804`: *“For the lineal slice only the cells
distinguishable by the reused analytical primitives … are populated;
others F.”* Lineal assembly `4082–4095` emits a representative 9-char
and fills the rest with `F`. Areal assembly maps miss → `-1` → `'F'`
(`4354–4368`).

`RELATE_MATRIX` already allowlists a whole-matrix decline
(`oracle/relate_matrix.ml` token `UNSUPPORTED`;
`RelateNGCore.v : relate_unsupported_no_predicate`). That is **Decline**
/ **Sentinel** in `CONTEXT.md`: claim-free, never a 9-char matrix. A
per-cell unknown is not Decline. CONTEXT has no name for it. This grill
does not invent one. The issue's proposed `?` stays a proposed token
until `/implement` of #523 and `/domain-modeling` resolve it.

### 3. Open cells are decided by an 80×80 grid probe

**Confirmed.** Header already says “probed by a grid” (`3778`). The
probe is `ng = 80` over the padded joint box (`4332–4358`). A miss
leaves `f_ii` / `f_ie` / `f_ei` false → cell `-1` → printed `F`
(`4356–4358`, `4368`). Exhausted-probe `F` means “no sample found”, not
`RelateCurveMatrix.v : cell_none_iff_empty`.

EE is the exception that proves the rule: the driver hardcodes
`cell_ee = 2` (`4359`), matching
`RelateCurveMatrix.v : geom_de9im_ee_nonempty` /
`two_geometries_exterior_meet`. That cell is established nonempty. The
open interior cells are not.

Tolerances `1e-12` / `1e-9` are live on the collinear and on-segment
tests (`3964`, `3974` and the areal copies). Interface-boundary float,
as the mode header already says.
