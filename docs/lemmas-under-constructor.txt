# Lemmas under constructor -- the ADR-0007 debt, frozen.
#
# Every entry here is Qed and true.  What it is not is a statement about the
# geometry a caller handed in: it consumes `fully_intersected` or
# `pairwise_nodable` as a HYPOTHESIS, and that premise is exactly the sentence
# "the cook already ran".  Until an oracle produces the arrangement, a proof
# downstream of that premise is a proof about whatever the oracle emitted, not
# about the input segments.
#
# Enforced by scripts/check_constructor_gate.py, which fails when this file
# and the tree disagree.  The gate does NOT break the build on the debt below;
# it freezes it.  Adding a line requires a justification comment above it.
# Removing a line means the lemma stopped consuming nodedness -- which is the
# outcome the route is for.
#
# Why this gate exists alongside mutation testing: a mutation checker asks
# "does this sentence weigh anything".  Mutate `fully_intersected` in
# `fully_intersected G -> snap_ok G` and the proof breaks, so the checker
# reports the hypothesis as load-bearing.  It is -- that is the problem.  An
# ABSENT constructor is not a mutation of any existing term, so mutation
# cannot see it.  This gate asks the other question: is the sentence about the
# input we accepted.
#
# Route out (ADR-0007, and the three obligations):
#   1. two-segment intersection: construct P with t,s; prove emptiness when
#      disjoint; classify overlap separately.  DONE, Qed, in
#      theories/ChordCook.v: `chord_hit` and `chord_hit_unique` (proper
#      crossing, unique t,s in (0,1)), `chord_miss` and
#      `chord_parallel_distinct_miss` (emptiness), `chord_collinear_overlap`
#      and `chord_collinear_from_points` (overlap as a subsegment, not a
#      point).  The pair oracle is complete and takes no non-degeneracy
#      hypothesis.
#   2. insert the points: cut every segment at every constructed point; then
#      two segments meet iff they share an endpoint.  THAT is
#      `fully_intersected`, as a conclusion.  CLOSED for chords in exact
#      reals with non-degenerate members, in theories/ChordCook.v:
#
#        cook   -- cuts at proper crossings only.  `cook_noded`,
#                  `cook_split_noded`.  The "if" half.
#        cook2  -- also cuts at the projected endpoints of collinear members
#                  (`coll_params`) and dedups with `nodup`.
#                  `cook2_split_noded_strict` is the "only if" half: two
#                  pieces meeting away from their endpoints are the same
#                  piece, or that piece reversed.  No collinear disjunct.
#        cook_covers / cook_within (and the cook2 forms) prove the image is
#                  the input as a point set, so `fun _ => nil` does not
#                  qualify.
#
#      Termination is structural: for straight pieces one pass is a fixed
#      point, because a proper crossing of two pieces is a proper crossing of
#      their parents (`subchord_cross_parent`), and because every cut
#      parameter of a collinear neighbour transports back
#      (`cut_param_transport`).
#
#      WHAT IS STILL ASSUMED.  `cook2_split_noded_strict` takes
#      non-degeneracy of every member as a hypothesis; a point-chord has no
#      direction to project onto.  `cook2` runs on such input and
#      `cook2_noded` still holds, but the strict conclusion is withheld.
#      Orientation is not normalised: a piece and its reverse remain two
#      entries and the theorem names the twin explicitly.
#
#      This does NOT discharge anything below.  Every entry below is stated
#      in binary64 over the corpus graph type; `cook2` runs on a list of
#      chords in R.  Three gaps separate them: the number type, the piece
#      classes (arcs and clothoids have no oracle, hence Decline), and the
#      graph (`cook2 G` is a list, not a DCEL -- no vertex identity, no
#      rotation system, no faces, no labelling against a second operand).
#      What `cook2` supplies is the SHAPE such a discharge must have.
#   3. round to a grid: two rounded edges meet iff they share an endpoint.
#      OPEN.  Do not assume (2) when proving (3).
